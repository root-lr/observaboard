# Feuille de route V2

La V2 rend ObservaBoard gérable depuis le central : l'« intégration en un clic » devient littérale, sans SSH. Le PRD complet, V1 à V3, décrit les objectifs. Cette page relie chaque chantier au code existant.

## Ordre conseillé

| # | Chantier (PRD) | Point de départ dans le code | Remarques |
| --- | --- | --- | --- |
| 1 | **G1 · API et registre central** | nouveau service `observa-api` dans `assets/central/docker-compose.yml.tmpl`, routé par Caddy (`/api/observa/*`) | Le registre remplace `central.yaml` (canaux) et `tokens.yaml`. Réutilisez `project.Config` comme modèle de projet. |
| 2 | **G2 · Configuration à distance des agents** | `internal/agent` : le rendu de `config.alloy` déménage vers l'API ; l'agent utilise le bloc `remotecfg` d'Alloy | Gardez `observa apply` comme mode hors ligne. ## Dettes connues de la V1

- **Dashboards :** un dossier par projet, généré à partir du registre, remplacera le filtre par variable.
- **Celery :** seule la file `celery` (base 0) est surveillée. Rendre la liste des files configurable sur le service Redis.
- **Disparitions volontaires :** les alertes « service arrêté » et « agent silencieux » restent actives 24 h après une suppression volontaire. Le registre V2 saura distinguer une suppression d'une panne.
- **Rotation du token :** elle passe aujourd'hui par une réinstallation de l'agent. Ajouter `observa agent rotate-token`.
- **Masquage des logs :** filtrer les motifs sensibles (tokens, emails, cartes) dans l'agent, avec `loki.process` et `stage.replace`.
